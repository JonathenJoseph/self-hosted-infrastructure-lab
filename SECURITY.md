

# Security Policy

## Scope

This repository is a documentation-led infrastructure portfolio. It does not distribute the live deployment configuration or provide access to the underlying home infrastructure.

Security concerns may relate to:

- Sensitive information accidentally included in documentation.
- Accidental publication of credentials or private configuration.
- Incorrect security statements.
- Unsafe technical guidance.
- Repository access or publication issues.

## Reporting a vulnerability or sensitive disclosure

Please do not publish credentials, exploit details or sensitive personal information in a public GitHub issue.

Use GitHub's **Private vulnerability reporting** facility for this repository when it is available.

The repository owner should enable this facility in the repository's Security settings before public release.

If private vulnerability reporting is unavailable, contact the repository owner through the contact options on the GitHub profile:

https://github.com/Unplayable-debug

Please include:

- A brief description of the issue.
- The affected file or repository area.
- The potential impact.
- Suggested steps to reproduce, where safe.
- Any suggested remediation.

Do not include live passwords, access tokens or private keys in a report.

## Response

Reports will be reviewed on a best-effort basis.

This is a personal portfolio repository. It does not provide a formal security response SLA, guaranteed resolution time or commercial security support.

## Supported content

The current repository version is the primary supported version.

Historical commits may contain older documentation. Please report any sensitive information discovered in historical content as well as in current files.

## Security limitations

This repository is not a production service and is not intended to provide security guarantees for any connected infrastructure.

Documentation of a security control does not prove that the control is currently enabled or effective.

Likewise, the absence of a documented vulnerability does not establish that a system is free from vulnerabilities.
